# 4. Glossary

This glossary defines the principal components, contracts, roles, and technical terms used in the AI Analytics Platform white paper. Logical architecture terms follow Section 2. Product-specific terms are identified as elements of the illustrative reference implementation in Section 3. Terms are sorted alphabetically, and cross-references to other entries are shown in **bold**.

| Term | Abbreviation | Definition |
|---|---|---|
| **Admin API** | N/A | An illustrative Section 3 service for governed administration of platform settings and authoring workflows. It is not an analytical execution path and does not grant analytical data access. **Data Entitlements Store (DES)** policies remain under the Entitlements Manager's control. |
| **AI Analytics Platform** | N/A | The proposed architecture for governed AI-enabled analytics and data mining. It combines bounded language interpretation with approved semantic definitions, deterministic planning and computation, entitlement enforcement, controls, structured presentation, and retained evidence. |
| **AI consumer** | N/A | A conversational assistant, autonomous agent, data-mining workflow, or custom application that submits an authenticated analytical request and presents the governed response. A consumer does not own analytical definitions, permissions, query planning, or governed computation. |
| **Analytical Lineage Store** | ALS | The evidence ledger for accepted analytical requests. It correlates request, intent, entitlement, validation, controls, planning, execution, presentation, artifact, response, and terminal events. Its integrity depends on enforced retention, authorization, signing or content addressing, reconciliation, and recovery controls rather than application convention alone. |
| **Authentication and identity token** | N/A | A host-issued credential carried through trusted request transport and validated at platform ingress. Verified identity claims are made available through server-side request context; the bearer token is not an analytical tool argument and is not exposed to a language model. Section 3 illustrates this contract with a **JSON Web Token (JWT)**. |
| **Compliance trigger** | N/A | The deterministic decision that additional provenance evidence is required. The proposed rule requires both a compliance-relevant metric signal and a compliance-purpose signal. A natural-language request receives the purpose signal from the **Intent Resolution Agent (IRA)** subject to threshold evaluation; a structured caller declares purpose through a validated field. Either signal alone is insufficient. |
| **Data Context Store** | DCS | The shared versioned storage and access service that houses the separate **Semantic Metrics Repository (SMR)** and **Semantic Data Repository (SDR)** in the illustrative architecture. It does not contain every platform policy or runtime record; the **DES** and **ALS** remain distinct responsibilities. |
| **Data Entitlements Store** | DES | The independent policy source for analytical access. It stores versioned policy for permitted metrics, dimensions, row scopes, column masks, and classification ceilings. The MCP layer uses a bounded policy view for catalog discovery, while the **Role-Aware Projection Layer (RAPL)** performs the full request-time entitlement evaluation. |
| **Data mining** | N/A | In this paper, the use of governed bulk datasets by an authorized research application, agent, or analytical process to investigate patterns or develop models. The platform controls dataset selection, fields, row scope, source state, pagination, export, and evidence. Downstream feature engineering, statistical analysis, model training, validation, and conclusions remain separately governed activities. |
| **Data Visualization Language** | DVL | The governed presentation contract produced deterministically from the approved intent, result schema, and registered presentation metadata. It returns a chart or table specification rather than a rendered image. An authorized caller may request a compatible governed override; incompatible presentation choices are rejected. |
| **Dataset contract** | N/A | An approved, versioned `analytical_dataset` definition in the **SMR**. It declares the permitted fields, classifications, selection rules, source mapping, ordering, pagination, and freshness expectations for governed data retrieval. |
| **Execution profile** | N/A | A field on an approved `analytical_operation` definition that controls optional response assembly after the mandatory governed pipeline has run. `data_retrieval` returns a governed dataset, `metric_query` adds a DVL specification, and `full_analytical` may also add an NSA narrative. The profile never bypasses entitlements, validation, controls, planning, execution, or lineage. **PAS** invocation is controlled by the **compliance trigger**, not by the execution profile. |
| **External language model service** | N/A | A model service called through bounded adapters by the **IRA** or **NSA**. It may rank approved candidates, suggest parameter bindings, or draft a narrative from permitted result content. It does not receive source credentials, authorize access, calculate governed metrics, or generate the executable physical query. |
| **Federated Query Engine** | FQE | The controlled execution boundary and the only logical component with registered backend connections and credentials. It admits approved physical execution envelopes, runs bounded source instructions, assembles compatible results, applies any remaining protections, and records execution evidence. |
| **Financial Services Reference Model** | FSRM | Illustrative Section 3 bundles of proposed SMR definitions for shared dimensions and selected financial-services domains. The bundles are seeded in `proposed` state and become resolvable only after governance approval. |
| **Intent confirmation card** | N/A | A structured choice returned when intent or compliance purpose is ambiguous. It presents ranked approved operations, bound parameters, material filters, and a presentation preview without executing a backend query or exposing physical schemas. |
| **Intent Resolution Agent** | IRA | The bounded AI component that translates natural language into an approved operation and typed parameters. It ranks candidates from an entitlement-scoped SMR catalog view, records confidence and purpose evidence, and requests confirmation when meaning is uncertain. It does not receive credentials, generate executable queries, or approve definitions. Structured requests that already identify an approved operation bypass the IRA. |
| **JSON Web Token** | JWT | The token format used for authentication and identity in the illustrative Section 3 implementation. The implementation validates its signature, issuer, audience, expiry, and required claims against trusted keys before analytical processing begins. |
| **Knowledge Store** | N/A | An illustrative Section 3 store of versioned, non-user-data guidance exposed read-only through MCP resources. Knowledge resources help consumers use the platform but do not provide an alternate analytical execution path. |
| **Logical Query Plan** | LQP | A backend-independent plan produced by the **Semantic Validation Layer (SVL)**. It carries pinned definition versions, logical calculations, filters, row scope, masks, compliance inputs, output shape, and other governed planning context. It contains no credentials, connection endpoints, physical table names, or executable SQL. |
| **MCP Capability Layer** | MCP | The single governed platform entry point. It authenticates requests, applies entitlement-aware tool and catalog discovery, accepts natural-language or structured operation requests, correlates the request, and returns the **Structured Response**. A structured request may bypass the IRA, but it still resolves an approved SMR operation and passes the complete entitlement and controls pipeline. |
| **Metric definition** | N/A | An approved, versioned SMR declaration of a metric's business meaning, formula or governed measure, aggregation behavior, units, compatible dimensions, classification, source affinity, mapping reference, owner, and tests. Access policy is maintained independently in the **DES**. |
| **Model Context Protocol** | MCP | The protocol used by the proposed platform to expose governed tools, resources, and prompts to AI consumers. The protocol does not itself provide semantic governance, entitlement enforcement, or analytical correctness. |
| **Narrative** | N/A | An optional plain-language explanation produced by the **Narrative Synthesis Agent (NSA)** from approved result labels, values, units, dimensions, and permitted derivations. Unsupported numbers, causes, recommendations, forecasts, or significance claims are rejected or omitted. |
| **Narrative Synthesis Agent** | NSA | The optional post-computation AI component that drafts a result-grounded narrative. A deterministic validator checks numbers, units, labels, comparison direction, and permitted derivations before release. Failure to produce a valid narrative does not change the computed data, DVL specification, lineage, or compliance evidence. |
| **Optional Rendering Service** | N/A | An external presentation utility that converts a self-contained DVL specification into SVG or PNG. It has no access to analytical definitions, source credentials, or execution backends and does not participate in governed computation. |
| **Physical Query Planner** | PQP | The deterministic boundary that resolves approved mappings and source capabilities for an LQP and produces a bounded physical execution envelope. It binds typed predicates, expands time periods, groups work by source, applies protection directives, and records plan integrity evidence without holding source credentials or executing the plan. |
| **Provenance Artifact** | N/A | A sealed, cryptographically signed evidence package produced when the **compliance trigger** is active. It binds the request and purpose evidence to the applicable definitions, entitlement decision, controls, plans, execution, result, and verification metadata. A valid signature establishes that the sealed bytes have not changed; it does not prove that the calculation is correct or legally sufficient. |
| **Provenance Artifact Service** | PAS | The component that assembles and seals a **Provenance Artifact** from the correlated ALS evidence set. It is invoked only when both compliance signals are active. Export remains blocked until sealing succeeds. PAS is independent of the execution profile and runs after the evidence required by the approved artifact contract is available. |
| **Registered data source** | N/A | A governed warehouse, lakehouse, semantic service, approved data API, relationship store, or multidimensional engine available to the FQE through an approved connection and mapping. Registration requires defined credentials, classifications, timeout behavior, capabilities, and failure semantics. |
| **Result Cache** | N/A | An optional cache inside the controlled execution boundary. Its canonical key includes the effective plan, tenant, entitlement projection, pinned definition versions, and relevant configuration. Every cache hit still passes current authorization and creates new lineage evidence. Compliance-purpose requests bypass the cache unless approved policy provides equivalent evidence and freshness guarantees. |
| **Role-Aware Projection Layer** | RAPL | The deterministic component that combines verified identity context with current DES policy to produce the caller's effective entitlement projection. The projection contains permitted concepts, row scope, masks, classification ceiling, policy versions, and decision evidence. |
| **Semantic Controls Layer** | SCL | The mandatory release gate between semantic validation and physical planning. It evaluates data scale, complexity, classification, compliance, and concurrency against versioned controls, assigns an execution timeout, records the decision, and rejects requests that may not proceed. When the compliance trigger is active, it marks the provenance artifact as required and export as blocked pending PAS. |
| **Semantic Data Repository** | SDR | The governed source of business and physical data metadata, including data models, critical data elements, quality rules, structures, mappings, profiling evidence, and data-lineage references. It is separate from the **SMR**, although both may use the **DCS**. Adoption requires a readiness assessment of its coverage, ownership, freshness, and mapping quality; the architecture does not assume that every organization already has a suitable SDR. |
| **Semantic Metrics Repository** | SMR | The governed catalog of approved analytical metrics, dimensions, operations, dataset contracts, presentation metadata, and mapping references. Definitions are owned, versioned, reviewed, and approved before governed resolution. The SMR defines analytical meaning; the **SDR** describes the underlying data context. Search indexes or embeddings may support discovery but do not change approval state or access rights. |
| **Semantic Validation Layer** | SVL | The deterministic semantic quality gate that receives a resolved request, entitlement projection, and approved SMR definitions and produces a backend-independent **LQP** or structured rejection. It validates parameters, pins versions, checks semantic compatibility, applies the entitlement projection, and attaches validated compliance inputs. No language model runs in this component. |
| **Structured Response** | N/A | The governed delivery envelope returned to a consumer. It distinguishes status, typed data or a data reference, DVL specification, optional narrative, lineage, compliance state, warnings, and errors. Consumers render this contract without recalculating or reinterpreting governed values. |
